# 云端压测与任务收束

这页聚焦云端托管的压测任务、异步状态查询和结果收束。端侧不再提供本地脚本或 k6 MCP 执行入口。

## 先判断是不是这页的范围

- 你要启动云端分布式压测任务并轮询状态、结果或取消任务：看这里
- 你要确认压测任务的通过条件、性能阈值和最终产物：看这里
- 你只是想验证单个协议请求、字段提取或断言：优先回到 [接口实战](playbook.api.md)
- 你要直接运行本地脚本：使用工作区自己的命令行和脚本工具，不走 Helix MCP

## 能力边界

- 云端负责托管任务、调度 worker、维护异步状态并统一收束结果
- 端侧只提交意图和任务参数，不在 Helix 中执行本地 k6 脚本
- 任务启动、状态查询、结果查询和取消是不同动作，不应合并成一次重复调用
- “任务已启动”只表示进入异步执行阶段，不代表任务已经通过

## 常见动作

云端压测通常包含四类动作：

- 启动任务
- 查询状态
- 查询结果
- 取消任务

常见输入来源：

- 启动一个已有的云端压测任务
- 提交脚本文本后由服务端创建任务
- 提交结构化压测规格后由服务端编译并创建任务

最小意图示例：

```text
启动一轮云端分布式压测，
目标是 keepalive 接口，
2 个虚拟用户，持续 3 秒，
要求响应状态码为 200。
```

任务启动后，后续动作应该改成：

```text
查询刚才那轮云端压测的状态。
```

或者：

```text
拉取那轮云端压测的归一化结果。
```

不要把已经启动的任务再次描述成待执行动作。

## 通过条件与阈值

压测通过条件通常分成两类：

- 功能条件：响应状态码、响应体关键字段或目标事件是否出现
- 性能阈值：失败率、P95、P99、吞吐或超时上限

建议先写功能条件，再写性能阈值。例如：

```text
要求响应状态码为 200，
失败率低于 1%，
P95 小于 200ms。
```

## 结果与产物

云端压测通常返回：

- 任务标识
- 当前状态
- 下一步建议动作
- 最终归一化结果或取消结果
- 服务端保留的汇总与诊断产物

需要长期回看或自动归档时，应保留任务结果和服务端产物，不要只依赖终端文本。
