# 性能实战

本页帮助你把“感觉变慢了”转成可复核的测试任务：固定场景，采集画面或指标，再比较多轮结果。设备与采样工具来自 Helix，运行前需连接目标设备、准备测试应用，并确认 `/tools` 中存在所需能力。

## 先判断是不是这页的范围

适用于端到端耗时、Android 内存或流畅度比较，以及随机扰动后的异常排查。服务端多用户负载测试见[云端压测](playbook.load.md)。

## 怎么读这页

| 指标 | 在本页中的含义 | 需要固定的条件 |
| --- | --- | --- |
| E2E | 从指定开始事件到指定结束事件的总耗时 | 明确起止画面和触发动作 |
| ASR 首字上屏 | 语音识别场景中，第一个文字出现的时点 | 音频输入与开始计时的事件 |
| VAD 尾字上屏 | 结合语音活动检测阶段观察最后文字出现 | 结束说话的判定与结束画面 |
| tokens/s | 流式输出速度 | 明确 token 计数来源与时间区间；屏幕字符数不能直接替代 token 数 |
| 内存 / FPS | 资源占用与画面流畅度 | 设备、版本、采样方式和相同操作路径 |

一句话理解：

- Framix 更偏视觉真值和阶段报告
- Memrix 更偏指标采样和趋势分析
- 扰动能力更偏稳定性扰动和异常发现

## 能力速览

| 类型 | 入口 |
|------|------|
| 视觉真值 | Framix 帧分析与阶段报告 |
| 指标采样 | Memrix 内存 / 流畅度 / 趋势对比 |
| 稳定性扰动 | 随机扰动 + logcat 异常留痕 |
| 典型跑法 | `mind exec "..." --helix` |

## E2E 耗时、ASR 首字上屏、VAD 尾字上屏、流式 tokens/s

```text
mind exec "录制完整交互流程并生成 Framix 阶段报告，关注 E2E、ASR 首字上屏、VAD 尾字上屏和流式 tokens/s" --helix
```

核心目标是先保留真实交互视频，再做视觉真值分析，最后把阶段结果沉淀成报告。

“视觉真值”在这里指可回看的实际画面证据。报告应注明如何识别起止事件、采样频率和未能观察到的阶段；只有录屏时，不应把推算的模型 token 数写成实测值。

## Android 内存基线

```text
mind exec "围绕首页进入路径重复采样 10 轮，输出 Java Heap、Native Heap 和 PSS 的分层内存基线报告" --helix
```

基线关注稳定路径的趋势，不以单次采样数字作为结论。

## Android 内存泄漏

```text
mind exec "重复执行首页到详情页再返回首页的路径，观察多轮后内存是否持续抬升并输出报告" --helix
```

泄漏判断关注重复进入退出后的趋势变化。

持续增长是进一步排查的线索，不应仅凭一次峰值直接认定内存泄漏。保留轮次、等待时长和各层内存数据，便于复现与比较。

## Android 流畅度

```text
mind exec "执行首页列表滚动路径并生成流畅度报告，观察 FPS、掉帧和卡顿趋势" --helix
```

流畅度验收关注完整图形路径，不只判断单次点击是否成功。

## Android 扰动

```text
mind exec "对 com.example.app 执行 5000 个随机事件，节流 200ms，保留核心导航键并检查崩溃、ANR 和异常日志" --helix
```

同类目标也可以用英文或日文描述，执行语义保持一致。需要持续回归时，应由外部脚本或调度系统固定输入、次数和验收条件。
