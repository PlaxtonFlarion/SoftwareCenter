# 产品背景与能力生态

本页介绍 Mind 的产品定位、使用场景和可选能力，帮助使用者理解各组件能解决什么问题。
它不定义系统 Authority、运行时所有权或跨仓生命周期：

- Mind、AppServer 与 Fabric 的系统边界以[系统架构](../ARCHITECTURE_SYSTEM.md)为准；
- ProxyMind 客户端内部边界以[客户端架构](../ARCHITECTURE.md)为准；
- 线上字段、端点、事件和错误以服务端正式契约及客户端 protocol 实现为准。

## 为什么需要 Mind

传统脚本适合稳定、重复的流程，但面对动态目标、跨工具协作和长时间任务时，通常需要维护
大量分支、上下文和补偿逻辑。Mind 把模型推理、工具调用、权限控制、过程观测和会话恢复组合
成一个统一的终端工作环境。

Mind 关注的是可交付执行，而不是只生成建议：

- 根据当前目标选择合适的本地或远端能力；
- 在执行前应用工具 schema、沙箱和审批约束；
- 以流式方式展示正文、工具、审批、重试和恢复状态；
- 保存恢复所需的本地证据，支持中断后继续观察；
- 让同一任务可以从 CLI、交互 TUI、stdio MCP 或订阅入口发起。

## 使用入口

| 入口 | 适合场景 |
| --- | --- |
| `mind` | 连续对话、交互审批、会话恢复和多轮工具协作 |
| `mind exec` | 单次目标、脚本调用和自动化验证 |
| `mind mcp-server` | 把 Mind 能力提供给其他 MCP host |
| `mind agent listen` | 接收远端任务并复用本地执行能力 |

这些入口共享同一组应用能力，但界面和交互方式不同。完整参数见[命令行使用参考](cli-usage.md)
和[交互模式](interactive-mode.md)。

## 能力组合

Mind 按当前会话组合三类工具来源：

- Native tools：文件、Shell、Git、补丁、计划和本地 JavaScript 等基础工程能力；
- External MCP：用户显式配置并连接的第三方 MCP 服务；
- Helix：按需接入的本地能力服务，提供设备、协议、媒体和性能相关工具。

工具可见不等于执行授权。每次调用仍受参数校验、沙箱、审批、网络策略和 Effect 规则约束。

### Helix

Mind 默认不依赖 Helix。只有任务需要对应能力时，才通过 `--helix` 或 `/helix-link` 显式接入。

Helix 面向以下能力方向：

- 设备与 UI 操作；
- API 协议执行、提取和断言；
- 媒体录制、抽帧、转码和音轨处理；
- 性能、稳定性和运行环境采样。

Helix 是可选能力提供者，不是 Mind 启动前置条件，也不在本页承担系统级生命周期定义。

## 工程与取证能力

Mind 的常见工程工作流包括：

- 读取代码、搜索依赖、运行测试并应用精确补丁；
- 调用数据库、浏览器或外部 MCP 完成跨系统任务；
- 对设备和应用执行可控操作并保留结果；
- 对接口进行请求、提取、断言和批量回放；
- 采集截图、录屏、性能指标和阶段报告；
- 在失败、中断或断线后恢复会话和必要证据。

每类能力的参数与限制由对应 playbook 维护，本页不复制工具契约。

## 产品生态

### Framix

Framix 面向视觉真值和阶段报告。它适合从截图、录屏或关键帧中识别页面状态、定位视觉目标，
并为端到端流程提供可复核的视觉证据。

### Memrix

Memrix 面向性能指标采样和趋势分析。它适合观察内存、流畅度、耗时和多轮运行趋势，并用于
基线比较与回归判断。

### Fabric

Fabric 提供可选的云端计算能力，例如 Sandbox、模型、Embedding、Rerank 和 Vision。它不是
Mind 的远程副本，也不是每个任务的必经组件。具体计算边界和恢复责任由系统架构定义。

### AppServer

AppServer 为联网会话提供持久生命周期和事件服务。用户通常通过 Mind 间接使用它；其状态
所有权、终态和恢复规则不在产品背景页展开。

## 典型场景

- 在一个交互会话中完成代码修改、测试和复核；
- 组合浏览器、数据库与 MCP 服务完成业务排查；
- 通过 Helix 执行设备流程、接口验证或媒体取证；
- 使用 Framix 对关键交互阶段生成视觉报告；
- 使用 Memrix 对多轮性能数据做趋势比较；
- 在需要隔离或专用算力时调用 Fabric 能力。
